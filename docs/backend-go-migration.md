# Go 后端迁移

开发沙箱、默认启动和发布产物均使用 Go 后端。旧 Bun 后端与历史 TS 对照工具已移除，保留静态 SQLite 结构与路由基线测试。

## 已确认的约束

- Go 固定使用 1.27.4；Vue、dou-ui 前端保留。
- 后端业务、内置 provider、插件宿主和发布程序迁到 Go，发布产物不依赖 Bun/Node。
- SSH 和 daemon 来源及其远程工作区转接不再提供；远程工作直接在远程机器部署 Ariadne。
- 用户允许升级插件接口，旧 TS/JS 插件需要适配，不要求原样运行旧插件源码。
- 保留现有 SQLite、配置文件和 token 格式，以及 HTTP JSON、SSE 和 Yjs WebSocket 协议。
- 现有认证、文件访问边界、命令审批、凭据隔离、缓存上限和协调器独立调度都属于迁移验收范围。

## 当前检查方式

```sh
go version

```

### 启动和打包

`bun run dev:sandbox` 通过临时配置、临时数据库和模拟 AI 服务启动 Go 后端，
同时启动 Vite。要单独启动后端并使用构建好的前端，可以运行 `go run ./cmd/ariadne`，
默认读取 `packages/web/dist`，也可以通过 `ARIADNE_WEB` 指定页面目录。

```sh
bun run build
go run ./tools/webbundle packages/web/dist cmd/ariadne/dist/web.zip
go test -tags ariadne_web -count=1 ./cmd/ariadne
go build -tags ariadne_web -trimpath -ldflags "-s -w" -o dist/ariadne ./cmd/ariadne
```

交叉编译时为 `go build` 设置 `CGO_ENABLED=0`、`GOOS`、`GOARCH`。发版构建可用
`-X main.version=<版本号>` 写入版本。Windows 产物使用 `.exe` 后缀。
内嵌构建提供 `--version`、`self-check` 和 `mcp-stdio` 命令，运行时只需要 Go 产物及所配置的外部工具。
同一套前端的 Windows x64 产物约 25 MiB（Go）和 151 MiB（旧 Bun），均关闭 UPX。

Go 模块最低版本和 CI 都固定为 1.27.4。CI 包含全平台原生测试（`native`）和 Linux 轻量竞态检测（`race`）。

Go 数据访问使用 `modernc.org/sqlite`，无需 CGO；Yjs 协议使用固定版本的
`github.com/antst/go-yjs`。文档、画板、仪表盘已验证状态往返和 Go 修改后的同步消息，
画板及仪表盘支持从已有协作状态恢复，并在 SQLite 中同一事务内保存版本和协作状态。
画板字段与仪表盘布局的修改基于旧版本计算差异。文档支持 Markdown 与编辑器块双向转换、内嵌画板、并发修改合并、草稿撤回和反馈保存。

已逐条对照项目、讨论串、会话状态、消息、通知、计划、审查、产物和搜索投影，
并验证供 agent 读取的会话记录及唤醒游标。完整重放测试使用旧后端的真实业务操作生成数据库，
比较所有业务表、视图和原始附件/协作状态；旧版本投影可从日志重建，失败会回滚原表及版本。
项目删除与新任务写入在同一写锁内检查，避免删除后仍写入任务。

已验证同一时刻普通和预留名额占满时，多个项目的协调器仍可启动，且同一会话不会并行启动两轮。
项目暂停会中断现有轮次，恢复后继续；启动时恢复上次中断的轮次，启动前取消不会误报未配置模型。
授权会按原有规则共享、使用和拒绝；应用重启后，不把结果未知的外部写入当作尚未执行。

产物内联图片和版本保存使用同一事务，校验失败不会遗留附件。线程增量同步缓存限制为
128 个项目、16 MiB 元数据、30 分钟过期；后台清理、删除和关闭都会释放内容。
两个 HTTP 模型 provider 都限制保留的工具/思考块数量和累计大小，避免异常流持续占用内存。

Codex app-server、Claude Code 与 ACP 已通过原生进程/协议测试及旧实现对照；
Codex 使用原生历史注入，并能在重启后恢复检查点和正确计算新增用量。
程序会话的空闲数量、过期时间、事件队列、待处理工具与检查点文件都有上限；
删除、取消和关闭会释放资源，活跃会话不会因空闲会话上限排队。
Claude Code/ACP 的工具桥接仅监听本机，使用随机路径令牌，校验 Host/Origin；
标准输入输出转接支持并行请求、取消和消息上限，已接入原生启动程序的 `mcp-stdio` 子命令。
Windows 已实测通过 `.cmd/.bat` 启动和包含中文、引号、空格及特殊字符的参数传递。

全局配置通过旧实现对照验证，包括空密钥保留、显式清除、角色默认值与回退、
模型支持的推理强度、指令/快捷键/限额校验、独立搜索服务和 MCP 设置。
保存失败会保留原内存配置；临时文件、并发更新及删除项目后的密钥清理均有回归测试。
独立搜索检查使用草稿配置，不会保存密钥；搜索请求不跟随重定向，HTTP 错误不包含响应正文。

模型目录采用一次下载、共享并发请求和 12 小时过期策略，限制原始数据、条目数和索引大小，
无人再访问时也会释放过期目录。模型解析只复制当前 provider 的配置，未再复制整份模型目录；
Windows 本机基准在保存 1 个与 2 万个模型时，单次解析均分配约 1.36 KB；这不是整机性能结果。

外部 MCP 已覆盖 stdio/HTTP、协议协商、工具分页、双向 ping、工具变更、取消及会话过期。
HTTP 调用完成或取消后关闭对应流，通过单独的 GET 流接收通知，避免保留每次调用的 SSE。
工具元数据缓存限制为 32 项、16 MiB、5 分钟，失败记录也有数量/大小/过期限制；
连接删除、配置变更、空闲淘汰和关闭均会清理资源，工具变更通知合并后再刷新。

本地工作区使用有边界的文件句柄，覆盖链接替换、`.git` 保护、关闭后的命令取消和目录锁释放。
独立工作区保留创建时的基础分支和项目子目录；同一讨论串的创建/快照/删除互斥，锁用完即释放。
Git 快照不修改真实索引；合并/撤销保留其他未提交的文件，冲突或存在后续引用时拒绝破坏分支。
依赖克隆失败会清理部分目录；关闭工厂会取消并等待探测和命令退出。
Linux/macOS 的原生克隆实现已交叉编译，实际文件系统行为仍由对应平台测试验证。

文件搜索已通过旧实现对照，包括 glob、忽略目录、二进制跳过、后向引用、前后查找和
UTF-16/emoji；逐文件回退搜索限制文件大小、遍历数量、匹配行数和正则执行时间。
目录排序仍有一项兼容差异：Go CLDR 与 ICU 的中英文脚本混排顺序不同，尚未完成对齐。

Git bundle 使用标准输入输出流传输，不把整个包放进内存；取消、关闭和未读取的流都会释放子进程。
引用更新采用事务并禁止解引用，失败不会部分更新，删除符号引用也不会删除其目标分支。
已用两个独立仓库验证托管组合中的下行同步、远端分支删除和上传提交。
来源连接会关闭失败、取消和校验完成后的临时资源；引用密钥只在配置指向同一主机时借用，
主来源不会收到其他引用的密钥。项目创建与来源/引用配置已通过旧 HTTP 实现对照，密钥不进入事件日志。
设置 schema 保留字段声明顺序，避免 JSON/RPC 往返后改变表单顺序。

托管仓库已通过实际 Git HTTP 获取/推送测试，凭据不写入克隆配置，也不会发给重定向目标。
多个项目连接同一克隆时按仓库串行更新；推送使用捕获的提交 SHA，推送期间新增的本地提交不会误报为已上传。
GitHub/GitLab 的 PR/MR、合并结果、CI 状态、日志、工单和评论已通过旧实现对照。
GitLab 根据实例隔离环境密钥与 glab 查询，自建实例带端口号时使用 Windows 可用的目录名称。
显式 GitLab 凭据的注册表有数量与大小上限。来源连接释放时移除对应凭据，应用退出时清空注册表。
环境与 CLI 凭据缓存 20 分钟，仓库元数据缓存 5 分钟，到期和关闭后会释放；缺失或失败的查找可重试。
REST 请求最多同时 128 个、总时长 30 秒、JSON 响应 16 MiB，错误正文限制为 64 KiB 并移除当前请求的令牌。
日志按流处理，只保留最后 2 万个 UTF-16 单元；GitLab 的 ANSI/章节标记也按流清理。
GitHub 允许日志下载到外站，跨站后不再携带鉴权；GitLab 保持拒绝重定向。
链接预览最多缓存 500 条/4 MiB/1 分钟，同一地址共享请求，卸载 provider 时清除缓存并取消请求。
原生测试已覆盖取消、上限、到期、删除/卸载、并发读取和关闭后的资源释放。

进程日志已迁移为原生实现，兼容旧 `processes.json`。启动的子进程会记录并在结束时删除，
日志原子替换，大小/条目数有上限；多个原生后端使用文件锁避免互相覆盖。
Windows 使用原生创建时间，Linux 使用启动标识与内核时钟，macOS 使用内核进程信息，
新记录包含更准确的进程身份，减少 PID 复用造成的误杀。
已验证日志清理、旧记录恢复、活跃 owner、写入失败回滚，以及实际后端进程退出后子进程的处理。
Windows Job 会在后端退出时释放子进程，Unix 的崩溃恢复测试等待对应平台 CI 执行。
Go CLI 在启动时打开日志，并在各服务退出后关闭它。

实时命令、回复草稿及终端文本清理已通过旧实现对照，SSE 接口已实测按项目补发当前命令、后台任务和草稿。
状态存储限制条目数、总大小与实际编码后的单帧大小；输出截断会复制保留部分，避免短尾部仍引用完整大字符串。
回归测试曾复现 32 MiB 输出截断后仍被保留，修复后 GC 验证通过；缓存关闭时也会清空查询回调，释放其捕获的配置。
替换、结束、删除和关闭会清理计时器，旧句柄不能恢复已删除的草稿。
后台任务已迁移增量读取、终端预览、服务地址识别、接管运行中的命令、停止和用户要求保留的任务。
每个讨论串最多运行 4 个，保留 8 个已结束任务；全局任务数、输出保留量和读者数量有上限，已结束输出 30 分钟过期。
已验证实际子进程停止后 Windows 工作目录可以改名，GET/停止任务接口也通过旧 HTTP 实现对照。
后台命令已接入工作区初始化脚本和讨论串执行循环。

来源、引用和工作区连接按配置共享，空闲数量与存活时间有上限；活跃操作持有句柄，独立协调器不会因空闲缓存上限排队。
旧视图在来源、凭据或 provider 变更后拒绝继续访问，删除和关闭会取消操作并释放资源。
空闲工作区只释放句柄，磁盘文件由单独的保留策略处理；重新打开时保留原分支和显式为空的 base。
初始化脚本只在新建时启动一次，使用项目的环境、shell 和超时；模型记录的脚本要通过命令规则，用户配置的脚本按原规则运行。
初始化状态和提示有数量、大小和过期限制。命令规则解析已覆盖复合命令、重定向、变量赋值、包装程序、嵌套 shell、PowerShell 编码命令和文本参数，并通过旧实现对照。
规则匹配与解析均有预算，无法完整检查的复杂命令进入询问流程。已验证一次批准只能运行一次指定命令，
换命令或工作目录需要按规则重新判断。
自动清理合并、关闭的 PR 和长期空闲工作区；长期保留会阻止自动清理，外部交付完成不会触发合并。
清理遇到活跃操作、应保留的后台任务或未提交文件时保留目录；停止超时会保留任务记录，避免误删仍被占用的目录。
AI 添加引用时保护本机凭据和应用数据路径，远程路径按原有拼写规则检查；手动配置仍按原流程处理。
已通过旧实现对照，并补上符号链接后接不存在子路径的保护。
工作区 API 已对照变更、文件版本、合并冲突/成功/撤销、外部交付拒绝合并、保留和删除响应。
用户合并的方式与结果在同一事务内记录，失败会全部回滚；并发项目删除共享清理，一个请求断开不会中断其他请求等待的删除。

模型上下文已对照工具结果排序、缺失结果、用户原话保留、指令更新、图片/附件、摘要及半步压缩位置。

该方式与完整历史生成的模型输入一致。结束回合也只读取未回答工具调用的标识，避免解码全部历史输出。

定时唤醒已覆盖过期等待、搁置恢复、例行任务的宽限期、重启跳过错过的任务和配置修改后的重新计时。
